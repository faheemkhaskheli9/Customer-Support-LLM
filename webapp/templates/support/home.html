WHAT THIS STAGE ADDS

{% if stage == 1 %}

First response

Trusted support instructions, one model call, and response metrics. Compare an unsupported policy answer with a focused clarification.

Try: “What is your warranty period?”

{% endif %} {% if stage == 2 %}

Conversation context

Messages are committed only after a successful response. The app keeps a bounded history in the server-side session.

Try: “My order is A123”, then “What is my order number?”

{% endif %} {% if stage == 3 %}

Structured routing

Valid routes are answer from approved information, clarify, handoff, or unsupported. An invalid model result fails safely.

Try: “Cancel my order” and “What is the return policy?”

{% endif %} {% if stage == 5 %}

Approved retrieval

Only approved, current passages for your region can be retrieved. Citations come from retrieval metadata, never from the model's text.

Try: “Can I return an opened item?”, “Is cash on delivery available?” with and without a region, and “Do you price match?”

{% endif %} {% if stage == 6 %}

Read-only tools

The only tool is order_status. The model proposes it as validated JSON; code checks the sign-in, ownership and a lookup limit on every call. Another customer's order gets the same reply as a missing one.

Try as customer A: “Where is order ORD-1001?”, “Where is order ORD-2001?” and “Cancel my order ORD-1001.”
